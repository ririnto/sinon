# Repository Guidelines

Each publishable package lives directly under `plugins/<plugin>/` and keeps its README, manifest, runtime files, scripts, tests, and assets inside that root.
The package root is the containment boundary for declared paths and packaged content.

## Package Contract

Keep the marketplace manifest aligned with package roots.
Keep manifests schema-valid, use object-form authors, and keep declared paths inside the package root.
Declare Codex identity in `.codex-plugin/plugin.json` and Claude Code identity in its marketplace entry.
Keep shared identity metadata aligned across both host catalogs and local manifests.
Keep a local `.claude-plugin/plugin.json` manifest's identity fields aligned with its marketplace entry.
Do not add root `plugin.json` files because they shadow native Codex manifests.
Declare Claude MCP servers inline in `.claude-plugin/plugin.json` and Codex MCP servers in `.codex-plugin/mcp.json`.
Declare each MCP transport explicitly and use a schema that matches its configuration.
Declare Codex MCP and custom hook paths with native `mcpServers` and `hooks` fields.
Keep default runtime locations undeclared unless a custom location is required.
Do not add generated byproducts unless they are tracked or required for validation.
Use each package README for its component inventory and supported runtime.

## Skill Content Authoring

Make each discovery description distinguish the task from neighboring skills.
Keep the deliverable, authority boundary, and first conditional reference visible when a skill loads.
Name local references by their distinguishing topic or version.
Check instructions from the installed package layout, including references opened by a host agent.

## Validation

Run `claude plugin validate .` after changing a package or its marketplace entry.
Portable Agent Skill structure belongs to the affected skill's contract.
