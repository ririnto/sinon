# Repository Guidelines

Each publishable package lives directly under `plugins/<plugin>/` and keeps its README, manifest, runtime files, scripts, and assets inside that root.
The package root is the containment boundary for declared paths and packaged content.

## Package Contract

Keep the marketplace manifest aligned with package roots.
Keep manifests schema-valid, use object-form authors, and keep declared paths inside the package root.
Declare portable identity in `plugin.json` and Claude Code identity in `.claude-plugin/plugin.json`.
Keep their shared identity metadata aligned with each other and the authoritative catalog.
Use portable `mcp.json` and Claude `.mcp.json` for their respective MCP consumers.
Declare each MCP transport explicitly and use a schema that matches its configuration.
Keep OpenAI-specific hook configuration under `extensions.com.openai` in the portable manifest.
Keep default runtime locations undeclared unless a custom location is required.
Do not add generated byproducts unless they are tracked or required for validation.
Use each package README for its component inventory and supported runtime.

## Skill Content Authoring

Local reference filenames omit parts redundant with the owning skill's subject while keeping the distinguishing topic or version.

## Validation

Run `claude plugin validate plugins/<plugin>` after changing that package.
Portable Agent Skill structure belongs to the affected skill's contract.
