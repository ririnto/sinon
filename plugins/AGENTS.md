# Repository Guidelines

This file applies to `plugins/`.
Closer plugin instructions override it.
Each publishable package lives directly under `plugins/<plugin>/` and keeps its README, manifest, runtime files, scripts, and assets inside that root.

## Project Structure

Use the plugin README for its layout and supported runtime components.
Use the owning plugin's nearer instructions for package-specific behavior.

## Build, Test, and Development Commands

Run `claude plugin validate plugins/<plugin>` after changing that package.

## Coding Style and Testing

Keep manifests schema-valid, use object-form authors, and keep declared paths inside the plugin root.
Keep default runtime locations undeclared unless a custom location is required.
Write English headings, language-tagged code fences, and BCP 14 terms in stable rules.
Follow the owning skill for portable Agent Skill structure.

## Commit and Publication

Do not add generated byproducts unless they are tracked or required for validation.

## Security and Configuration

Review plugin runtime components and packaged assets for filesystem, command, network, credential, and publication effects.
Open the package README when you need its component inventory.

## Scope and Precedence

Do not copy package-specific behavior into this file.
