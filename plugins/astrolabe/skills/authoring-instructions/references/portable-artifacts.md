# Portable Artifacts

Open this reference only when an instruction package contains conditional, heavy, or runtime-sensitive portability detail.

## Keep Package Boundaries Explicit

Keep every runtime asset and declared path inside the owning package root.

Use package-relative paths, stable command names, schema identifiers, and documented runtime contracts.

Name required runtimes and optional validators without assuming a user-global path, network service, credential, or external process state.

Do not add generated byproducts unless the package tracks them or validation requires them.

## Move Conditional and Heavy Detail Out of the Main Skill

Keep `SKILL.md` focused on the trigger, common rule, and next action.

Move branch-specific procedures, exhaustive option tables, large native-tool records, and runtime-sensitive details into the owning `references/` directory.

Link each reference from its owner and state the condition that requires loading it.

Keep temporary plans, scratch files, and generated helpers outside the package unless the user requests them as deliverables.
