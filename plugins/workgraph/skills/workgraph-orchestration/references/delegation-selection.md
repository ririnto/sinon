# Delegation Selection

## Choose the Graph First

Use a direct Graph when the Main Agent can finish from current evidence with a narrow sequence of actions.

Use one worker lane when a sizeable outcome benefits from isolated context or sustained ownership.

Use a reconnaissance lane when discovery is broad, uncertain, or likely to flood the Main Agent with working I/O.

Use a planned Graph when several workers have genuine design or dependency relationships.

Add a verifier or curator only when fresh judgment, independent evidence, or raw-material compression materially improves the result.

## Concurrency

Dispatch every dependency-independent lane concurrently.

Overlapping logical paths may run concurrently in isolated physical copies when routine integration can reconcile them.

Serialize work when a design, interface, or semantic decision determines downstream implementation, or when shared mutable state cannot be isolated safely.

## Capability and Effort

Choose the least costly model and effort level that satisfies the node's acceptance criteria.

Name the selected model explicitly in the dispatch when the platform supports model selection.

Use a low-cost general worker for bounded exploration, extraction, summarization, and mechanical implementation.

Use a stronger worker for subtle debugging, complex multi-file implementation, adversarial review, or evidence that requires judgment.

Reserve the highest-capability Main Agent for architecture, graph synthesis, authority decisions, conflict resolution, and final integration.

Effort controls reasoning intensity rather than completeness or response length.

Start low for routine work and raise effort only when the task itself requires deeper reasoning.

Do not create a verification node merely to repeat checks the owning node or Main Agent can already perform from current evidence.
