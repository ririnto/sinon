# PR-First Review

Remote publication requires separate authorization.
Never push directly to protected branches or the named base branch.

When remote publication is separately authorized, push the feature branch and open or update its pull request for delivery.
Run an independent review of the complete change before integration.
Review the posted change when the change is published, and keep review evidence current with the delivered head.
When publication is not authorized, review the complete local candidate instead and mark integration pending.
Ensure all required checks pass and resolve all acceptance blockers before normal integration.
Review completion and passing checks do not authorize normal integration.
Confirm the integration grant and follow the selected repository merge strategy.
